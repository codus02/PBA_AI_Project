## 3. End-to-End 환경 비교 (사용자 체감)

### 3-1. 측정 환경
Track 1 의 두 e2e 측정 그대로 사용. **둘 다 동일 환경 (rerank ON)** → 직접 비교 가능.

| 측정 | 모드 | rerank | retrieve_n | ranking |
|---|---|---|---|---|
| 베이스라인 e2e (2B prompt) | e2e | **ON** | 50 | pre-H1 |
| 어댑터 e2e (final) | e2e | **ON** | 100 | H7a 적용 |

### 3-2. 추천 메트릭 비교 (실서비스 환경)

| 지표 | 베이스라인 e2e | 어댑터 e2e (final) | Δ |
|---|---|---|---|
| **Hit@1 (labeled)** | 9.42% | **57.59%** | **+48.17p** |
| **Hit@3 (labeled)** | 22.25% | **79.84%** | **+57.59p** |
| **Cat Hit@3 (labeled)** | 67.80% | **94.50%** | **+26.70p** |
| **Cat Hit@3 (all)** | 63.38% | **85.65%** | **+22.27p** |

= **사용자가 실제로 받는 추천 품질이 Hit@1 +48.17p 개선.**

### 3-3. +48.17p 분해 (해석)

| 기여 요소 | 추정 효과 | 측정 근거 |
|---|---|---|
| **ranking 가설** (H1~H5 + H7a) | ~+7p | Track 2 oracle 비교 (61.3% → 68.3%) |
| **슬롯 추출 정확도 + retrieve_n 확장** (어댑터 + retrieve_n 100) | **~+41p** (나머지) | 전체 +48p − ranking +7p |

→ **추천 품질의 절대 다수 (~85%) 를 슬롯 추출 정확도가 좌우.**
→ ranking 가설 기여 (~15%) 도 의미 있지만, **슬롯 추출 자체 품질이 e2e 결과를 결정적으로 견인.**

### 3-4. 인사이트

**Track 1 슬롯 메트릭만 보면 +80p (taste F1) 큰 개선이지만, 그 효과가 추천 단계까지 흘러내려가서 e2e 에선 +48p 로 나타남.**
**Track 2 ranking 의 +7p 는 oracle 천장 기준이라 e2e 에서도 비슷하게 +7p 정도 기여.**

= 슬롯 추출 정확도가 추천 시스템의 사용자 체감 품질에 직접적이고 큰 영향. ranking 튜닝은 보조적.

## 4. 발표 스토리

### 출발점 (현재 시스템의 문제)
- 슬롯 추출이 너무 안 됨: taste F1 16.1%, aroma 13.1% (2B prompt baseline)
- → 추천도 맞춤 안 됨: **e2e Hit@1 9.42%** (사용자 체감 품질 매우 낮음)

### 시도한 접근

**[1] 슬롯 추출 모델 개선** (Track 1)
- 모델 사이즈 ↑ (9B prompt) → taste 87%, aroma 82%, 메모리 부담
- 파인튜닝 (2B + LoRA 어댑터) → **taste 96%, aroma 95%, mood 96%** (9B 보다도 높음 + 메모리 효율)

**[2] 추천 ranking 별도 개선** (Track 2)
- 점수 함수 4 가설 (H1~H5) → +3.9p
- retrieval pool 확장 (H7a) → +3.1p
- → **oracle Hit@1 61.3% → 68.3%** (+7p, 순수 ranking 효과)

**[3] 통합 결과** (End-to-End, 사용자 체감)
- 1번의 슬롯 모델이 추천 결과에도 직접 영향
- → **e2e Hit@1 9.4% → 57.6% (+48p)**
- 분해: ranking 가설 ~+7p, **슬롯 추출 영향 ~+41p**
- = "슬롯 추출이 추천 품질의 절대 다수 좌우" 입증

### 최종 채택
- 슬롯 추출: **2B + LoRA 어댑터**
- 추천 ranking: **H7a 적용** (점수 함수 + retrieval pool 확장)
- 데모용 베이스라인 확정
