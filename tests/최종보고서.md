### 2-4. 핵심 인사이트

**점수 함수 4 라운드 튜닝 (+3.9p) ≈ retrieval pool 1줄 변경 (+3.1p).**
→ 단일 단계 깊이 파는 것보다 파이프라인 전 단계 점검이 더 효율적.

**시도했지만 채택 안 한 변경:**
- H6 (MockVector slot-derived): 결과 악화로 보류 (`exp/gemma-h5` 브랜치 보존)
- H7d (쿼리 어휘 정렬): 0건 변동 → 롤백. 단어 페어 거리는 의미 있지만 풀 쿼리에선 dilute. 진짜 fix 는 임베딩 도메인 fine-tuning (post-demo, H7c)

## 3. 발표 스토리

### 출발점
**2B prompt 베이스라인** 으로 슬롯 추출 측정 → taste F1 16.1%, aroma 13.1% (사용 불가능 수준)

### 시도한 접근
1. **모델 사이즈 ↑**: 9B prompt 으로 변경 → taste 87%, aroma 82% (합격선이지만 메모리 부담)
2. **파인튜닝**: 2B + LoRA 어댑터 학습 → taste 96.1%, aroma 95.1%, mood 95.9% (9B 보다도 높음)
3. **추천 ranking 별도 개선**: 점수 함수 (H1~H5) + retrieval (H7a) 가설 검증 → Hit@1 61.26% → 68.32%

### 최종 채택
- 슬롯 추출: **2B + LoRA 어댑터** (베이스라인 대비 +80p, 9B prompt 보다도 높음 + 메모리 효율)
- 추천 ranking: **H7a 적용** (점수 함수 + retrieval pool 확장)

### 결과
- 슬롯 추출: 모든 지표 90% 이상 (strength 75.8% 만 약점)
- 추천 ranking: oracle Hit@1 68.32%, Hit@3 88.22%, Cat Hit@3 96.60%
